# naturable-rules

Open, explainable rules for spotting AI-sounding writing: assistant chatter, template openers, vague sources, stacked hedges, AI vocabulary (*delve, leverage, robust…*), em-dash habits, and Chinese translationese. Each rule says **why** a phrase reads as AI-ish and **what to do instead**.

- **Try it:** paste a draft at **[naturable.app](https://naturable.app/en/)**. It runs in your browser and nothing is uploaded.
- **Chrome extension:** underlines these patterns where you type (Gmail, LinkedIn, Notion…). [Coming soon](https://naturable.app/en/chrome-extension/)
- **Agent Skill:** `skill/` for Claude Code, Codex and other agents. [Install](#agent-skill)
- **CLI / npm:** `npx naturable-check draft.md` · `import { engine } from "naturable-rules"`
- **Word list:** [AI words to avoid](https://naturable.app/en/ai-words-to-avoid/), with [CSV](https://naturable.app/downloads/ai-words-to-avoid.csv) and [JSON](https://naturable.app/downloads/ai-words-to-avoid.json) downloads

> **Not an AI detector.** A hit is a style signal, not evidence of who wrote the text. This project does not help text evade AI detectors and won't add rules for that.

## Rule packs

| Pack | Version | Rules | Status |
|---|---|---|---|
| English `packs/en.json` | en-v1.1 | 23 | stable |
| Chinese `packs/zh.json` | zh-v1.1 | 16 (+4 rejected, documented) | beta |

Rules run in four layers. On overlapping text the earlier layer wins:

1. **hollow**: claims without substance (vague sources, generic conclusions, fake certainty)
2. **structure**: template shapes (not-just-but, signposts, stock conclusions, dense dashes)
3. **artifact**: assistant leftovers (*Great question!*, *As of my last update…*)
4. **lexicon**: word-level habits (AI diction, filler phrases, stacked hedges)

The full readable list is in [`skill/references/rules-en.md`](skill/references/rules-en.md) and [`rules-zh.md`](skill/references/rules-zh.md).

## Use it

### JavaScript (browser, extension, worker, Node)

```js
import { engine } from "naturable-rules";

const { issues, score } = engine.analyze(text, { purpose: "blog", language: "auto" });
// issues[i]: { rule: { id, title, severity, reason, suggestion, … }, start, end, text, document }
// score.total: 0–100 pattern score (NOT an AI-authorship probability)

const fixed = engine.autofix(text, issues);     // applies only auto-safe rules, never drops numbers/names
const one   = engine.applyIssue(text, issues[0]); // { ok, text, reason }
```

The engine is stateless. Ignore lists, undo history and storage belong to the caller:
`engine.scan(text, { ignoredRules: new Set([...]), ignoredKeys: new Set([...]) })`.

Without a bundler: `dist/naturable.iife.js` exposes `window.Naturable`.

### CLI

```bash
npx naturable-check draft.md                    # readable report
npx naturable-check draft.md --json             # for tools and agents
npx naturable-check draft.md --fix              # auto-safe fixes only
cat email.txt | npx naturable-check --purpose email
```

### Agent Skill

Copy `skill/` into your agent's skills folder. For Claude Code:

```bash
git clone --depth 1 https://github.com/GUCCI-atlasv/naturable-rules /tmp/naturable-rules
cp -R /tmp/naturable-rules/skill ~/.claude/skills/naturable-writing-check
```

Then ask: *"Check this draft for AI writing patterns."* The skill lists each hit with its reason and a link to the rule, and it rewrites only what you approve. It includes the rules reference and a self-contained checker (`skill/scripts/naturable-check.mjs`, Node 18+, no install).

## Rule format

Each rule is JSON ([schema](schema/rule-pack.schema.json)):

```json
{
  "id": "en.artifact.chat",
  "name_en": "Assistant chatter",
  "layer": "artifact",
  "category": "artifact",
  "severity": "strong",
  "confidence": "high",
  "purpose_weights": { "blog": 1.3, "academic": 1.4 },
  "detect": { "type": "regex", "pattern": "\\b(Great question[!.]?|I hope this helps[!.]?)", "flags": "gi" },
  "reason": "Leftover assistant phrasing distracts from the document.",
  "rewrite": "Delete the aside and address the reader directly.",
  "before": "Great question! Ship weekly.",
  "after": "Ship weekly.",
  "auto": true,
  "fix": { "type": "delete" },
  "evidence_policy": "keep_numbers"
}
```

- `before` must trigger the rule and `after` must not. CI checks this for every rule.
- `auto: true` only when the fix can't change meaning. Every auto fix also passes an information-conservation gate: no numbers dropped or invented, no new proper names.
- `evidence_policy: never_invent` tells rewriters (human or AI) not to make up sources or figures.

## Contributing a rule

1. Add it to `packs/en.json` or `packs/zh.json` with real `before` / `after` examples.
2. Name the false positives you know about in the PR (where the pattern is legitimate).
3. `npm run check` (validate → test → build) must pass.
4. Rules that only make text "pass detectors", or that push everyone toward one style, will be declined.

## Development

```bash
npm install

```
